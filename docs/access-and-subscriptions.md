# کاربران، سازمان‌ها و اشتراک هور+

هر سازمان فضای مستقل برای کانال‌ها، جریان‌ها، محتوای تولیدشده، اتصال‌ها و تنظیمات هوش مصنوعی دارد. مدیر سازمان اعضای همان سازمان را ایجاد می‌کند و نقش و دامنه کانال و جریان را تعیین می‌کند. `null` یعنی همه منابع سازمان، آرایه خالی یعنی هیچ منبعی. مدیر دسترسی کامل سازمان دارد.

ورود جدید با شماره موبایل و رمز است. شماره‌های ایرانی با ۰۹، ۹، +۹۸ یا ۰۰۹۸ و ارقام فارسی یکسان‌سازی می‌شوند. شماره تا اتصال سرویس پیامک تأییدشده محسوب نمی‌شود. مدیر رمز اولیه را به عضو می‌دهد؛ عضو پیش از استفاده باید رمز خود را تغییر دهد. ارسال خودکار رمز یا پیامک پیاده نشده است. مدیر می‌تواند دسترسی عضویت را قطع یا رمز اولیه جدید تعیین کند. رمز ذخیره‌شده قابل مشاهده نیست. حساب قدیمی بدون موبایل موقتاً با ایمیل قدیمی وارد می‌شود و از صفحه تغییر رمز موبایل خود را ثبت می‌کند؛ پس از آن ورود ایمیلی آن حساب بسته است.

نقش‌ها: مدیر، ویرایشگر، بررسی‌کننده، ناشر و مشاهده‌گر. ویرایشگر اجازه شروع اجرای جریان یا فعال‌سازی انتشار خودکار ندارد. تأیید بررسی‌کننده ممکن است طبق جریان از پیش تنظیم‌شده انتشار را ادامه دهد. حقوق در API بررسی می‌شوند و صرفاً مخفی‌کردن دکمه‌ها نیستند. عضویت و نقش در هر درخواست دوباره خوانده می‌شوند؛ تغییر رمز توکن‌های قبلی را باطل می‌کند.

## فعال‌سازی مدیر کل

روی **API** متغیر محیطی `HOOR_PLATFORM_ADMIN_USER_IDS` را برابر UUID حساب فعلی صاحب سامانه قرار دهید؛ برای چند مدیر UUIDها را با کاما جدا کنید. شناسه حساب در پاسخ احراز هویت و صفحه حساب موجود است. این تنظیم عمداً شماره فرضی یا اولین صاحب سازمان را خودکار مدیر کل نمی‌کند. سپس API را راه‌اندازی مجدد و دوباره وارد شوید. پنل «مدیریت سامانه» برای حساب مجاز نمایش داده می‌شود. تعیین این مقدار دسترسی به همه سازمان‌ها می‌دهد و فقط در تنظیمات محرمانه استقرار انجام شود.

مدیر کل سازمان و مدیر اولیه آن را می‌سازد، اشتراک را دستی فعال/تمدید/متوقف می‌کند و اطلاعات کانال، جریان، اجرا، مصرف AI و رویدادهای مدیریتی را می‌بیند. این دسترسی در گزارش فعالیت ثبت می‌شود. کلید اتصال، رمز و توکن در پنل نمایش داده نمی‌شود. درگاه پرداخت و تمدید خودکار بخشی از این نسخه نیست.

## اشتراک

هر سازمان طرح، وضعیت و تاریخ پایان مستقل دارد. سقف اعضای فعال، کانال‌ها، جریان‌های فعال و توکن AI قابل تنظیم است؛ مقدار خالی به معنای بدون سقف است. داده قدیمی اشتراک legacy فعال بدون سقف دریافت می‌کند تا مهاجرت کار جاری را قطع نکند. سازمان جدید طرح آزمایشی دریافت می‌کند و مدیر کل تنظیمات آن را تغییر می‌دهد.

با پایان یا توقف اشتراک، شروع پردازش و انتشار جدید در API و worker مسدود می‌شود؛ داده‌های قبلی حفظ می‌شوند. سقف منابع داخل همان تراکنش ایجاد/فعال‌سازی و با قفل سازمان بررسی می‌شود. اعتبار AI پیش از درخواست رزرو و با مصرف گزارش‌شده تسویه می‌شود. خطای شبکه با نتیجه نامعلوم اعتبار رزروشده را نگه می‌دارد تا retry باعث مصرف ثبت‌نشده نشود؛ این رزروها نباید بدون بررسی سرویس‌دهنده پاک شوند.

## استقرار

مهاجرت افزایشی `0012_tenant_access.sql` باید قبل از API و worker جدید اجرا شود. راه‌اندازی خودکار موجود آن را زیر قفل مهاجرت اجرا می‌کند؛ با `HOOR_AUTO_MIGRATE=false` اجرای دستی لازم است. نسخه web/API/worker هماهنگ باشد. برای قطع دسترسی، عضویت را غیرفعال کنید؛ حذف داده سازمان یا رمزگذاری مجدد لازم نیست.
