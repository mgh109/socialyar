# نتیجه اجرا و بازیابی انتشار

پایان پردازش جریان به معنی انتشار نیست. API جزئیات اجرا، `processingSummary` و `publicationSummary` را جدا برمی‌گرداند. پیش‌نویس فقط وقتی وجود دارد که مرحله پیش‌نویس متن کامل ساخته باشد؛ نام دلخواه کارت و شکست شاخه دیگر مانع دسترسی به آن نیست. نسخه‌های مقصد، صف و رسید انتشار مستقل‌اند.

## بازیابی

- اجرای گراف و انتشار هر پیام با قفل اختصاصی PostgreSQL انجام می‌شوند. قطع اتصال قفل، ادامه اقدام خارجی را متوقف می‌کند؛ پردازه‌های این نسخه باید از همین قرارداد استفاده کنند.
- تأیید انسانی، تغییر مرحله و ثبت رویداد در یک transaction ثبت می‌شوند. قطع Redis تصمیم را لغو نمی‌کند؛ رکورد queued و `dispatchVersion` قصد ادامه اجرا را حفظ می‌کنند.
- worker هر ۳۰ ثانیه کارهای ثبت‌شده‌ای را که job ندارند با شناسه نسخه‌دار برمی‌گرداند. انتشارهای تأییدشده و موعدرسیده بازیابی می‌شوند؛ زمان آینده، محتوای تأییدنشده و نسخه قدیمی مجوز ارسال نیستند.
- قطع پردازه پس از پایان گراف و پیش از آماده‌سازی صف با نشانگر `publicationPrepared` بازیابی می‌شود. خطای آماده‌سازی در نتیجه اجرا و رویدادها ثبت می‌شود.
- در انتشار معلق، نبود مرز شروع ارسال در نسخه جدید اجازه بازیابی می‌دهد. اگر ارسال آغاز شده باشد و رسید قطعی ذخیره نشده باشد، وضعیت نامعلوم ثبت و ارسال خودکار متوقف می‌شود. رسید تأییدشده فقط وضعیت محلی را ترمیم می‌کند و دوباره ارسال نمی‌شود.

## استقرار

۱. worker نسخه قبلی را متوقف کنید و منتظر پایان کارهای فعال بمانید. در زمان گذار، worker قدیمی و جدید را هم‌زمان اجرا نکنید؛ نسخه قدیمی قرارداد قفل جدید را رعایت نمی‌کند.
۲. migration افزایشی `0011_execution_recovery.sql` را پیش از شروع نسخه جدید اعمال کنید. در حالت معمول `ensurePublishingStorage` آن را در شروع API و worker اجرا می‌کند؛ اگر `HOOR_AUTO_MIGRATE=false` است، اجرای دستی لازم است.
۳. API، web و worker را از یک commit راه‌اندازی کنید. فضای رسانه مشترک و کلید رمزگذاری قبلی را حفظ کنید.
۴. ارسال‌های معلق نسخه قدیمی در اولین migration محافظه‌کارانه نامعلوم در نظر گرفته می‌شوند؛ بررسی مقصد پیش از تکرار لازم است. اجرای دوباره migration، مرز ارسال‌های نسخه جدید را تغییر نمی‌دهد.
۵. روی حساب آزمایشی، ورود محتوا، تأیید، موعد انتشار، رسید مقصد و بازیابی پس از قطع worker را بررسی کنید.

## آزمون‌ها

```bash
pnpm typecheck
pnpm --filter @socialyar/api test:integrity
pnpm --filter @socialyar/api test:collections
pnpm --filter @socialyar/worker test:reliability
pnpm --filter @socialyar/worker exec node --import tsx --test src/calendar.test.ts src/youtube.test.ts src/publishing-connection.test.ts src/content-collection.test.ts src/shared-collections.test.ts
pnpm --filter @socialyar/web build
```

آزمون‌ها از PGlite، صف و پاسخ مقصد آزمایشی و اتصال قفل شبیه‌سازی‌شده استفاده می‌کنند؛ انتشار واقعی یا قطع کامل شبکه تولید را تأیید نمی‌کنند.
