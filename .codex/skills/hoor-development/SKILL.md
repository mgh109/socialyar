# توسعه هور+

## شروع کار

1. `AGENTS.md` ریشه و قواعد نزدیک فایل‌های هدف را بخوان. وضعیت Git و تغییرات موجود را بررسی کن.
2. رفتار فعلی را از کد استخراج کن؛ حافظه مکالمه یا مستندات را تضمین قابلیت فعال فرض نکن.
3. مسیر کامل تغییر را مشخص کن: ورودی کاربر → API → پایگاه داده/صف → worker → نتیجه و وضعیت رابط.

## نقشه پروژه

- `apps/web`: رابط Next.js؛ `app/components/workflow-builder.tsx` بوم و تنظیمات کارت، `connections-manager.tsx` اتصال‌ها، `collection-panel.tsx` مجموعه‌ها، `app/styles.css` استایل‌های مشترک.
- `apps/api`: مسیرها، اعتبارسنجی و دسترسی؛ `src/routes/workflows.ts` قالب خروجی AI، تبدیل تنظیمات و ذخیره جریان.
- `packages/ai/src/index.ts`: دستورهای سازنده جریان و سرویس‌های متن AI.
- `packages/workflow/src/graph.ts`: نوع کارت‌های مجاز و قواعد اتصال.
- `apps/worker`: دریافت منابع، آماده‌سازی رسانه، اجرای کار و انتشار.
- `packages/db`: schema، migration و ابزارهای مشترک؛ فایل واقعی را با جست‌وجو پیدا کن.
- `docs`: راهنمای مجموعه‌ها، یوتیوب، تقویم و پروکسی. در تغییر قرارداد یا تنظیمات، راهنمای مرتبط را به‌روز کن.

## افزودن کارت یا تنظیم

1. نام و type کارت و قرارداد config را تعیین کن؛ از یک مفهوم با چند نام ناسازگار اجتناب کن.
2. فهرست کارت‌ها، مقدار پیش‌فرض، فرم، متن راهنما، وضعیت زنده و قواعد اتصال بوم را تطبیق بده.
3. schema و قواعد گراف و ذخیره API را تطبیق بده؛ هنگام تبدیل خروجی AI، تنظیم جدید را حذف نکن.
4. دستورهای `generateWorkflowBlueprint`، enum خروجی، تشخیص source، چیدمان و هشدارهای تنظیم ناقص را تطبیق بده.
5. پشتیبانی اجراکننده و worker را بررسی کن. برای قابلیت اجرا‌نشده کارت جعلی نساز؛ محدودیت را دقیق بیان کن.
6. اگر schema تغییر می‌کند migration افزایشی و سازگار با داده موجود اضافه کن.
7. رفتار معتبر، تنظیم ناقص و اتصال نامعتبر را بررسی کن؛ برای منطق غیرساده آزمون معنادار اضافه کن.

## رابط و فارسی‌نویسی

- برچسب‌ها را کوتاه و عملی بنویس: «اتصال»، «بررسی ارتباط»، «ذخیره»، «انتشار»؛ خطا باید علت قابل‌فهم و اقدام بعدی داشته باشد.
- کلاس‌های موجود مانند `primary-button`، `ghost-button` و `danger-button` را بررسی و استفاده کن.
- اقدام اصلی را واضح و اقدام فرعی را کم‌رنگ‌تر نمایش بده. تنظیمات مختص یوتیوب را هنگام انتخاب سایر کانال‌ها نشان نده.
- متن طولانی، حالت busy/disabled، صفحه کوچک، RTL و تم‌ها را بررسی کن. loader و وضعیت زنده را به کار واقعی وصل کن.

## منابع و انتشار

- شناسه پایدار محتوا، نسخه صف، ارسال موفق قبلی، توقف/لغو و نتیجه نامعلوم را حفظ کن. retry نباید ارسال موفق را تکرار کند.
- پیش از گرفتن فایل، قرارداد لینک و محدودیت رسانه را بررسی کن. شکست دریافت ویدئو را موفقیت دریافت محتوا معرفی نکن.
- در گوگل‌شیت، خواندن، snapshot، ورود، تأیید و انتشار مراحل مستقل‌اند. خودکاربودن refresh به معنی تأیید خودکار نیست.
- زمان‌بندی را از قرارداد شیت و timezone صریح بخوان. زمان گذشته را بدون توضیح به ارسال فوری تبدیل نکن.
- توکن هر حساب را در workspace خودش نگه دار؛ OAuth برنامه را با اتصال حساب کاربر اشتباه نگیر.
- محدودیت واقعی مقصد، نوع ویدئو و کاور را از کد و مستند رسمی بررسی کن؛ برچسب Shorts به‌تنهایی تضمین پذیرش مقصد نیست.

## بررسی و تحویل

- اسکریپت‌های `package.json` فعلی را بخوان. برای تغییر TypeScript، typecheck بسته مرتبط؛ برای تغییر منطق، آزمون‌های مرتبط؛ برای تغییر build، build لازم را اجرا کن.
- برای تغییر ظاهری، در صورت دسترسی پیش‌نمایش را بررسی کن؛ اگر بررسی بصری ممکن نشد، این محدودیت را اعلام کن.
- نمونه خطای گذشته را معیار پذیرش قرار بده: کارت مجموعه باید در دستور AI و schema مجاز باشد، تنظیمات شیت حفظ شود و گراف اجرایی معتبر بسازد.
- diff را برای تغییر ناخواسته و اطلاعات محرمانه بازبینی کن. فایل‌های همین کار را ثبت کن و طبق مجوز موجود به مخزن ارسال کن.
- نتیجه را کوتاه گزارش کن: چه رفتار تغییر کرد، چه بررسی شد، چه محدودیتی باقی است و آیا روی سایت منتشر شده است.
