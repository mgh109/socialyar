# هور+

سامانه ساخت جریان، تأیید محتوا و انتشار در کانال‌های متصل.

## Architecture

- `apps/web` — Next.js product UI
- `apps/api` — Fastify API
- `apps/worker` — BullMQ workflow worker
- `packages/workflow` — workflow runtime
- `packages/ai` — model/provider abstraction
- `packages/channels` — social publishing adapters
- `packages/db` — DB schema/migrations package
- `packages/shared` — shared schemas/types
- `packages/ui` — design tokens/UI primitives

## مسیر قابل اجرا

ورود → جریان با متن دستی → اجرای ورودی → تأیید انسانی → پیش‌نویس → ویرایش نسخه کانال → تأیید انتشار → انتخاب حساب مقصد و زمان‌بندی → وضعیت انتشار در تقویم و گزارش.

برای آزمون محلی، Postgres و Redis را با `docker compose up -d postgres redis` راه بیندازید، مهاجرت‌های دیتابیس را اجرا کنید و API، worker و web را با تنظیمات `.env` شروع کنید. برای ورود، حساب کاربری موجود در دیتابیس لازم است. تنظیمات نمونه و دسترسی کانال آزمایشی باید پیش از آزمون انتشار فراهم شوند.

انتشار تلگرام با Bot API انجام می‌شود. اتصال وب‌سایت یک webhook می‌خواهد که پس از ثبت موفق، JSON شامل `id` و در صورت امکان `url` برگرداند. درخواست شامل `publicationId` و هدر `Idempotency-Key` است؛ webhook باید با این شناسه جلوی ثبت تکراری در تلاش‌های مجدد را بگیرد.

شاخه‌های شرطی و اتصال بومی اینستاگرام، X و لینکدین هنوز پیاده‌سازی نشده‌اند. اجرای مرحله پشتیبانی‌نشده با خطای مشخص متوقف می‌شود.

## پایش خبر و ایتا

قبل از انتشار نسخه جدید، `packages/db/migrations/0002_eitaa_automation.sql` را روی همان دیتابیس API اجرا کنید. متغیر `HOOR_SECRET_KEY` را با `openssl rand -base64 32` بسازید و **یک مقدار یکسان** روی API و worker قرار دهید؛ تغییر آن بعد از ذخیره توکن‌ها باعث می‌شود قابل خواندن نباشند. توکن‌ها در دیتابیس رمزگذاری می‌شوند و در پاسخ API برنمی‌گردند.

در بخش اتصال‌ها، توکن ایتایار و شناسه کانال را ثبت کنید؛ سپس در تنظیمات AI، سرویس GapGPT، OpenAI API یا OpenRouter، مدل و کلید API همان سرویس را ذخیره و آزمایش کنید. برای GapGPT کلید را از پنل و نام مدل را از مستندات خود GapGPT بگیرید. اگر OpenAI API را انتخاب می‌کنید، کلید را از پلتفرم OpenAI بگیرید؛ اشتراک ChatGPT به‌تنهایی برای اتصال API کافی نیست. میز کار تازه خالی است: کارت منبع RSS را اضافه کنید و سپس هر مرحلهٔ دلخواه، مثل بازنویسی AI، تأیید انسانی یا انتشار ایتا را به مسیر بیفزایید. برای انتشار در ایتا، کانال را در کارت انتشار انتخاب کنید و جریان را فعال کنید. کارت ایتا و کارت AI اجباری نیستند. worker هر پنج دقیقه تا سه خبر تازه خوراک را بررسی می‌کند. شناسه هر خبر برای هر جریان ثبت می‌شود تا در نظرسنجی‌های بعدی دوباره وارد صف نشود. اگر کارت AI را اضافه کرده باشید خبر با مدل بازنویسی می‌شود؛ اگر کارت انتشار ایتا را اضافه کرده باشید متن برای ایتا صف می‌گیرد. کارت تأیید انسانی، ادامهٔ همان خبر را تا تصمیم شما متوقف می‌کند. گزینه‌های اینستاگرام، تلگرام، بله و X فعلاً در بوم غیرفعال نمایش داده می‌شوند.

در این نسخه، RSS منبع خبر است و اعتبارسنجی مستقل ادعای خبر انجام نمی‌شود. انتشار خودکار در ایتا به خاطر نداشتن شناسهٔ جلوگیری از تکرار در API کانال فقط یک بار به‌طور خودکار تلاش می‌شود؛ خطا در تاریخچه انتشار قابل مشاهده است. پیش از فعال‌سازی روی کانال اصلی، با کانال آزمایشی تست کنید.
